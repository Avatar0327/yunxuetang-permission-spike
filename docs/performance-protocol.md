# 04§9.5 实测协议

此协议细化测量口径，保留用户已经锁定的门槛。原始输出中的失败、拒绝、修复前数据全部保留。没有运行的阶段不得填写通过。

## 环境与数据

PostgreSQL4vCPU/8GiB、两个API容器各2vCPU/4GiB、独立Redis。固定镜像digest和同一代码提交；记录PG设置、池大小、索引与Docker limits。VM10vCPU/24GiB，负载客户端在主机运行。机器是同机本地实验环境；结果不证明生产多机网络、媒体带宽或1万人同时在学容量。

主租户50,000人，第二租户至少500人，约2,000部门/20层、至少20角色、三个公司、共享项目、1,000,000条历史事实。实测前通过SQL保存实际计数，不能用seed配置代替。部门21层/循环拒绝另有功能证据。

## 请求与统计

1. 每个参考窗口50个有效并发客户端持续600秒，两个API实例均参与。包含普通列表（先授权过滤，再分页及count）和复杂历史聚合；同时包含广范围内部身份及受限部门/客户身份。每类独立统计，保留精确请求配比和每个窗口开始/结束时刻。
2. Native与Casbin同一场景集、资源限制和数据。对象微基准只作解释材料，不能代替端到端性能。Casbin若不能进入合法批量查询契约，明确记录该候选缺证/不适配，不把Native SQL的性能冒充Casbin结果。
3. 热缓存与授权快照冷缓存分开运行及标记。冷缓存指L1/L2授权快照确实未命中；记录是否同时重启DB、数据页是否预热。不得用“冷缓存”笼统指代所有缓存都冷。另保存进程冷启动阶段；任何缓存优化仍每次读取DB权威版本及检查Redis可用性。
4. 合法请求、业务拒绝、基础设施故障分别保存样本和p50/p95/p99、数量、HTTP/业务错误率。独立拒绝和Redis故障窗口不并入正常查询性能。正常接口若返回200却错误少数据/泄漏/字段错误，计授权错误，不算成功性能样本。
5. 权限额外耗时包括权威版本与账号读取、Redis检查、快照读取/构建、范围解析和授权SQL计划生成（包括池等待）；不只计纯函数。列表时延包含权限、数据和count查询以及HTTP响应。聚合独立统计。记录每页20/50/200的查询次数，验证不随行数增长。
6. 原始记录保留候选、实例、场景、缓存态、合法性分类、状态码、请求时间、各时延及查询次数。可用压缩JSONL或完整延迟数组加完整计数；采样日志须标明采样比例，不能由采样数声称完整错误数。异常请求全部保留。

## 门槛

| 分类 | 必须同时满足 |
|---|---|
| 有效请求权限额外耗时 | p95≤50ms，冷热分别判断 |
| 有效普通列表（含过滤/count） | p95≤500ms，冷热和范围类别分别展示 |
| 有效复杂历史聚合 | p95≤2s，独立于普通列表 |
| 正确性 | 授权错误0；无越租户/公司/范围/字段泄漏；无N+1 |
| 撤权/故障 | A提交撤权后B下一新请求与媒体分片失效；PubSub丢失仍生效；Redis断连/超时/重连、DB权威失败均不放行 |

任何一项缺证或未达门槛，最终结论为No-Go。正式B1权限开发不得启动；需要整改时列具体失败项和复测范围，不移动门槛。

## 原始正确性记录格式（测量落地说明，门槛不变）

每个HTTP200响应均记录`actualCandidate`（服务端meta值）、`actualCount`、`rowCount`、`resultDigest`；不是每200次抽样一次。摘要保留实际开始/结束时间、实际durationMs及配置并发，原始样本保留clientId，便于独立核对50个客户端确实参与和600秒实际持续时间。

每个窗口旁保存`scenario-truth.json`：`formatVersion:1`、独立夹具算法说明，以及以场景名为键的`scenarios`；每项包含`expectedCount`、`rowCount`、`resultDigest`和完整`expectedRows`。摘要的`truthFile`指向该文件。真值来自合成数据生成规则的独立算式/常量，不调用生产PolicyService、Compiler或待测查询输出。

摘要比较对象为完整`{count,rows}`，不删除意外字段。对象键排序后序列化并SHA-256；列表/聚合行顺序保留，行内`source_ids`按字符串排序（来源集合的顺序无业务意义，重复值不去除），并在真值文件写明该规范。错误行/字段/数量/分组/合计或候选/缓存标签错误均单独计授权/测量错误，不混入成功时延。
